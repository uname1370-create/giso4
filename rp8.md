**3D Site Design Principles (از محتوای واقعی 3d site.md):**
- Core Operating Principle: Understand → Specify → Decide → Research when useful → Architect → Design → Build → Run → Inspect → Measure → Refine → Deliver — Not rigid checklist — Dynamic determine what user actually wants, what exists, what needs 3D, what should remain HTML/CSS
- Language and Input Independence: Persian/English/mixed informal incomplete — Respond in user's language
- Input and Project-State Detection: CREATE/EXTEND/MODIFY/REDESIGN/INTEGRATE/HYBRID — Don't ask if files can establish fact
- Intent Understanding: What visitor should accomplish, understand, feel, interact — Not every mention of 3D means entire website should become 3D
- Intent → Experience Specification: User Goal, Experience Scope (one element/component/section/page/flow/complete website), 3D Scope (full 3D, 3D hero, 3D product area, 3D background/environment, 3D interaction, 3D configurator, 3D transition, hybrid 3D+HTML/CSS, mostly HTML with selective 3D), UX (primary actions, navigation, interaction model, hierarchy, feedback, states, transitions, mobile), Content (known/missing/placeholder/user-provided/must not invent), Constraints (platform, browser, device, performance, existing architecture, deployment, accessibility, SEO, licensing)
- Scope and Ambiguity: explicitly required / strongly implied / safely inferable / unknown / outcome-changing unknowns / non-critical unknowns — Ask only when missing decision materially affects result and cannot reasonably be inferred
- Requirement and Constraint Resolution: Detect conflicts — cinematic quality vs low device cost, heavy simulation vs mobile performance, complex 3D vs fast loading, visual-only canvas vs accessible semantic content — Preserve core intent, approximate, choose implementation that satisfies most important goals, make trade-offs explicit
- Experience Architecture: Site Structure pages/routes/navigation/shared experiences/transitions, Information Architecture content hierarchy/primary-secondary actions/user flow/discoverability, 3D/2D Responsibility HTML/CSS/canvas/3D scene/overlays/interaction layer, Interaction Model User Action→System State→Spatial Response→Visual Response→UI Response, Experience States loading/intro/idle/hover/selected/expanded/transitioning/active/error/fallback/reduced-motion
- Research Intelligence: Optional triggered by value not habit — Determine question, whether research can improve, what source, how current — Sources relevance/quality/authority/technical reliability/recency — Extract principles/techniques/constraints/insights
- Reference Analysis: Treat references as research not templates — Analyze composition/spatial hierarchy/visual language/lighting/materials/camera/motion/interaction/UI-3D relationships/techniques/performance — Extract principles not branding/exact composition/layout/assets/code/animation
- Creative Direction: Concept/narrative/mood/emotional target/visual hierarchy/focal subject/composition/scale/depth/camera/lighting/materials/environment/atmosphere/motion/interaction/typography/color/UI-3D relationship/responsive — 3D must serve concept and UX — Don't add effects merely because possible
- 3D Spatial Design: Foreground/midground/background, real depth, perspective, object scale, negative space, framing, focal depth, occlusion, environment, spatial relationships, HTML/3D relationships — Perspective or Orthographic per intent — Camera parameters from composition not arbitrary defaults
- Camera Direction: FOV/distance/position/target/framing/perspective/movement/scroll-driven/pointer/touch/parallax/depth-focus/responsive states — Movement must support experience not decoration
- Lighting and Materials: Key/fill/rim, environment, HDRI, shadows, reflections, refractions, transmission, glass, metal, skin, fabric, ceramic, crystal, pearl, transparent, emissive — Physically plausible prioritizing intended visual result
- Geometry/Shaders/Particles/Simulation/Effects: Modeled/procedural geometry, shaders, particles, post-processing, volumetric, displacement, procedural animation, physics, simulation only when meaningfully contribute — Simplest technique that achieves required quality — Cheaper technique if quality not materially reduced
- Specialized 3D System Detection: Virtual Try-On, Product Configurator, garment, cloth simulation, skinned meshes, morph targets, body/face tracking, character, facial animation, hair systems, physics, fluid, procedural environments, product visualization, AR, WebXR, advanced shader, 3D editors — Identify requirements, research, architecture, browser/device constraints, only required realism — Don't treat specialized as decorative
- Asset Strategy: Created procedurally/modeled/generated/sourced externally/adapted/reused/combined — 3D models GLB/GLTF, textures, HDRIs, fonts, animations, characters, garments, products, environments, audio — Evaluate before integration
- Asset Pipeline: Acquire/Create → Inspect → Validate → Convert → Optimize → Compress → Integrate → Test → Fallback — Inspect polygon/triangle count, topology, materials, texture resolution/format, UVs, animation, skeleton, morph targets, compression, file size, loading cost, visual quality
- Asset Acquisition and Licensing: Source reliability, license, commercial use, attribution, redistribution, modification rights, format, quality, optimization cost — Unclear licensing not production-ready
- Technical Direction: Choose technology after understanding experience — Three.js/R3F/Babylon.js/WebGL/WebGPU/GLSL/WGSL/GSAP/post-processing/particle/physics/Blender/GLTF/HTML/CSS/Canvas — Based on requirements/existing architecture/performance/maintainability/browser support/complexity/constraints/deployment
- Technology and Dependency Validation: Before adopting library/API/rendering path/dependency validate suitability/browser support/API status/compatibility/maintenance/architectural fit/performance/necessity — Prefer supported maintainable — Don't add merely popular
- Technical Architecture: Rendering/UI/state/assets/animation/interaction/scene management/responsive/routing/data flow/backend/API — Proportional to complexity — Avoid chaotic and unnecessary enterprise abstraction
- Existing Project Strategy: Inspect structure, identify framework/language/build system/dependencies/routes/entry points/relevant files, understand current behavior, run when possible, inspect result, identify reusable architecture/assets, smallest appropriate change, preserve working architecture, modify/extend rather than rewrite — Preserve routes/components/content/dependencies/styling/deployment/working integrations — If only 3D enhancement needed don't rebuild entire website
- Build: Clean/maintainable/modular/reusable/no duplication/supported APIs/consistent architecture — Avoid over-engineering — Build experience not isolated demos
- UI and 3D Integration: Decide what belongs in semantic HTML/CSS/3D/overlays/transitions/interaction layers — Important semantic content not only inside canvas when HTML possible — 3D enhance interface not make essential information inaccessible — For commerce product info/pricing/actions/navigation/important content remain usable independently of purely visual 3D effects
